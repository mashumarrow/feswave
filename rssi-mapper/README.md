# ESP32 2台のWi-Fi RSSIマッピング実験

左にESP32-WROOM-32D、右にUNO R4 WiFi内蔵のESP32-S3またはもう1台のWROOM-32Dを置き、Wi-Fi対応スマホで、このスマホの信号が左右どちらの受信機で強いかを表示する。左のESP32がアクセスポイントとWebサーバーを兼ねる。外部ルーター、インターネット、スマホアプリは不要。2台とも基板アンテナを使う。

## 書き込み

左のWROOM-32Dには `left` を書き込む。USBシリアル付きの4 MB開発ボードを想定する。CLIコマンドはこのディレクトリで実行し、ポート名は `pio device list` で確認する。

```sh
pio run -e left -t upload --upload-port /dev/ttyUSB0
```

### 右にUNO R4 WiFiを使う場合

`uno-r4-right` は内蔵のESP32-S3-MINI-1-N8（8 MB）を直接プログラムする。測定ファームを書き込むと、S3が担当する標準USBブリッジとWiFiS3用の通信機能は、公式ファームを復元するまで使えなくなる。[Arduino公式の復元手順](https://support.arduino.cc/hc/en-us/articles/16379769332892-Restore-the-USB-connectivity-firmware-on-UNO-R4-WiFi-with-espflash)

1. UNOの電源とUSBを外す。USB-C近くの6ピンESPヘッダーで、4番 `DOWNLOAD`（GPIO0）と6番 `GND` をジャンパーで短絡し、その状態でUSBを接続する。認識後にジャンパーを外す。[公式ピン配置図](https://docs.arduino.cc/resources/pinouts/ABX00087-full-pinout.pdf)
2. `pio device list` で Espressif USB JTAG/serial（VID:PID `303A:1001`）のポート名を確認し、次を実行する。

   ```sh
   pio run -e uno-r4-right -t upload --upload-port /dev/ttyACM0
   ```

3. 書き込み完了後、ジャンパーが外れていることを確認してUSBをつなぎ直す。左を起動し、スマホの測定画面で「右受信機 接続中」と左右のRSSIを確認する。機種が違うため、設置後に中央の補正を取り直す。

### 右にもWROOM-32Dを使う場合

右用ボードを接続し、`pio run -e right -t upload --upload-port /dev/ttyUSB0` を実行する。

## 試し方

1. 左右のボードを例として3 m離し、アンテナを同じ向き・高さにして給電する。
2. スマホをWi-Fi **FESWAVE-RSSI**（パスワード **feswave-test**）に接続する。「インターネットなし」と表示されても接続を維持し、ブラウザで **http://192.168.4.1/** を開く。
3. 「右受信機 接続中」と左右それぞれのdBm値を確認する。中央でスマホの向きを固定し、値が落ち着いたら「ここを中央として補正」を押す。補正はページを閉じるか再読み込みすると解除される。
4. 画面を開いたまま左端→中央→右端と移動し、各地点で数秒止まる。左右のdBm、推定、表示が切り替わるまでの時間を比較する。スマホの向きや人の立ち位置を変えて繰り返すと遮蔽の影響も見られる。

複数のスマホで開く場合、各画面はそのスマホ自身を表示する。APの接続枠は右受信機1台とスマホ最大3台。右が接続待ちなら書き込んだ環境と電源を、両側または片側の値が「—」ならスマホが専用Wi-Fiに接続され画面を開いていること、および受信機との距離を確認する。シリアルモニターは115200 bps。

## 判定の仕組み

左は2.4 GHzのチャネル6で動作し、右はそこに接続して測定結果を400 msごとにUDP送信する。両方の受信機が、左AP宛ての上りデータフレームを送信元MACごとに集計する。ブラウザの約500 ms間隔の問い合わせが測定用の通信を兼ねる。左はDHCPのIP・MAC対応から表示対象を選ぶ。測定値はRAM上のみで保持する。

各受信機でRSSIを平滑化し、右RSSI − 左RSSI から中央の補正値を引く。差が +4 dB超なら右、−4 dB未満なら左、その間なら左右同程度と表示する。4 dBは実験用の初期値。各局が最近受信したフレームを比較する方式で、同一パケットの対応付けは行わない。片側の観測または右の通信が2.5秒以上途切れると判定を消す。

表示は左右の受信強度の傾向であり、距離や2次元座標を表さない。設置場所の反射、人体、基板やスマホの向きにより表示が逆転することもある。

## 正解位置と比較する

左受信機のUSBシリアル（115200 bps）をPCでファイルに記録する。スマホで中央補正を一度行い、左・中央・右の各地点に着いてから「位置を記録」の対応するボタンを押し、12秒間静止する。同じページで折り返すと往路・復路を別の試行として比較できる。各問い合わせに対して左受信機が時刻、ページ識別子、試行番号、正解位置、中央補正値、左右の測定値を `SAMPLE,` 行に出力する。ページ再読み込みで識別子と補正はリセットされる。

シリアルログを `python3 tools/summarize.py ログファイル` に渡すと、各試行の有効件数、正解数、左右・中央の判定内訳、補正後RSSI差の中央値を確認できる。スマホから左受信機に届かなかった問い合わせはログに含まれない。

## ADBでスマホの表示をリアルタイムに観測する

USBデバッグを許可したAndroid端末でChromeの測定画面を開き、PCで `node tools/watch-phone.mjs`（Node 22以降、adb）を実行する。約0.5秒ごとにスマホ画面の左右RSSI、補正値、判定、接続状態をJSON Linesで出力する。保存するには `node tools/watch-phone.mjs | tee /tmp/rssi-walk.jsonl` を使う。画面の表示を読み取るため、同じ測定値が複数行に現れることがある。USBをつないだまま測定し、終了はCtrl+C。複数端末を接続している場合は `ANDROID_SERIAL` で選択する。
